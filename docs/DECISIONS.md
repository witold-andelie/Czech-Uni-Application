# 决策记录

- D01 已确定：内置 zh-CN / en / cs，不依赖浏览器翻译。来源：用户明确要求。
- D02 已确定：留学入口首先按英语／捷克语授课分流，界面语言独立。来源：用户明确要求。
- D03 已确定：直观、美观、易懂；以 UI_RULES 的具体布局和验收落实。
- D04 已确定：难采集网页使用本机 Scrapling；已检查 CLI，实际来源抓取待实施。
- D05 已确定：OPM 指 ISO 19450，使用 DOT 交付。当前版本采用 ISO 19450:2024，公开映射差异。
- D06 设计决定：并列展示两种授课语言，不依据中文 UI 自动选择英语项目。
- D07 设计决定：岗位库独立于学位项目库，用工作语言和博士要求筛选。
- D08 设计决定：事实与译文绑定版本，三语审核后发布；过期／撤回状态及时更新。
- D09 性能选型：Go 在线服务，TypeScript/Astro 静态前台＋Svelte 局部交互，Python/Scrapling 离线采集，SQL/PostgreSQL；Node 仅构建使用。来源：用户要求综合性能和启动速度。
- D10 数据库建议：试运行用 Supabase Free 并独立备份，正式运营按可用性和配额决定升级；尚未开户或购买。
- 待后续决定：品牌、域名、部署区域、技术栈具体版本、初始学科与学校范围、内容审核人员。
- 目前交付是项目模型和实施约束，尚未建设或部署应用，也没有执行申请投递。

- D11 用户确定：每隔五天自动采集高校相关信息，高校覆盖必须广。
- D12 用户确定：关闭的岗位自动下架，岗位点击直达官方申请页面。
- D13 实施细化：以 120 小时间隔持久调度；已知截止即时计时，补充每日岗位轻量核查；网络失败与真实关闭分开处理。

- D14 用户确定：显著标注学校性质及中留服认证相关信息；采用官方查询参考和来源日期，不能承诺个人获认证。
- D15 用户确定：项目／岗位申请起止时间、官方存在的轮次必须显示。未知不补造，轮次关闭和整个机会关闭分别处理。
