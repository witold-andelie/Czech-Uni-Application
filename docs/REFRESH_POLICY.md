# 五天刷新、广覆盖与岗位申请规则

用户确定的产品策略：每隔五天自动爬取高校相关信息，广泛覆盖捷克高校，关闭岗位自动下架，点击岗位直接跳转申请页面。
本文件及 `config/refresh-policy.json` 描述仓库中已经实现并通过本地测试的采集分流：稳定高校资料每个 UTC 日处理五分之一，五天一轮覆盖全集；高波动来源使用独立短周期，不等待学校分片。worker 只写 `data/sources/` 和 `work/`，不直接写 `data/published/`。常驻调度尚未部署，不能描述为自动采集已经开启。

## 调度与运行

UTC 锚点固定为 2026-09-01。当天分片 = (UTC 日期 − 锚点) mod 5。学校的**初始**分片按官方 id 排序后取模，并写入 `work/runs/shard-assignments.json`。之后同一 id 保持原分片；名录新增学校加入当前最小分片，删除学校不让邻居轮转。没有这份持久映射时，不能声称分片“永远”不变。稳定学校资料按此分片；岗位状态、岗位发现、DZS 项目可用性和三条 CZU 项目任务不跟随学校分片。
每天只跑当前分片，不把五天工作挤进一天。普通漏跑：该分片等到下一个同余日，不叠加历史批次。若某分片距上次成功已超过 120 小时，才作为 SLA 补跑进入 `overdue_catchup`，每次唤醒优先最久未成功的一个分片。这是为了满足 120 小时全覆盖，不是把五天工作挤进一天。详见 `docs/SCHEDULER.md`。
同一全量任务不重叠。`refresh.lock` 使用跨平台操作系统文件互斥，不以 `exists → write` 充当锁；调度状态事务也在同一互斥内执行。租约保存 owner、token、续期时间和到期时间，只允许拥有者释放，过期后可回收。采集与每日岗位复核修改同一候选数据时共用全局锁。
逐来源保存最近尝试、最近成功、失败原因、`retryAt` 和 SLA。抓取失败、解析为空或分页不完整不推进成功时间；每日计划、补跑和循环入口都尊重 5 分钟、30 分钟、2 小时退避。失败状态继续参加各自周期与 120 小时上限检查，下一次唤醒会考虑最近的任务到期或重试时刻。
岗位适配器对幂等的官方 HTML／PDF 读取只在传输失败或 HTTP 408、425、429、500、502、503、504 时作两次有限重试，间隔 3 秒和 12 秒；其他 HTTP 状态直接返回。两次后仍失败时按来源失败处理，不推进成功时间、不触发目录消失归档，并进入上述任务级 `retryAt` 退避。2026-09-11 的一次 CTU 校级与 FEE 短暂失败先正确形成 8/10 部分运行，随后完整重跑恢复 10/10。

高波动任务的当前周期为：已知岗位状态与申请链接每 1 小时；所有已登记官方岗位目录完整发现每 4 小时；DZS 英文／捷克文项目全集与开放申请信号每 2 小时；CZU `study.czu.cz` 英语本科／硕士目录、`studuj.czu.cz` 捷克入口本科／硕士目录，以及以 MŠMT 博士库存为分母的六学院招生证据各自独立每 2 小时。DZS 只作项目发现交叉核对，MŠMT 仍是法定高校／项目基线，学校和院系页面仍是申请窗口权威来源；DZS 开放筛选中缺席不得写成关闭。CZU 两条本科／硕士来源分别按官网声明范围报告完整性并保留英语项目差异；博士源只主张 MŠMT 基线与已配置学院年度证据的逐项匹配，不把缺少开始日、条件轮次或尚未公告的新学年推断为开放。

命令：`py -3 services/ingestion/src/worker.py --once`（当天稳定五分之一）；`--recheck-jobs`（1 小时状态任务）；`--discover-jobs`（4 小时全部已登记岗位目录）；`--refresh-programme-availability`（2 小时 DZS 项目目录）；`--refresh-czu-programmes`（2 小时 CZU 英语项目与窗口）；`--refresh-czu-czech-programmes`（2 小时 CZU 捷克入口本科／硕士目录）；`--refresh-czu-doctoral-programmes`（2 小时 CZU 博士学院证据）；`--dry-run` 只打印计划；`--loop` 持续运行本地循环。来源级任务按域名限速；重试超限进入人工队列，长任务超出下一轮时间报告积压。

CZU 英语适配器先核对 WordPress REST 的 `X-WP-Total` 与 `X-WP-TotalPages`，再逐项读取所有官方详情，并另外读取开放项目页和通用申请页。2026-09-11 实跑为 36/36 详情、36 条完整窗口、35 条即将开放、1 条旧轮次关闭，当前日期判定与开放页均为 0 条开放。捷克入口的 REST 被访问控制限制，因此另一适配器独立核对首页总数、公开 programme sitemap 与唯一详情 ID，再读取所有详情和招生页；同日实跑三者均为 129，含捷克语 94、英语 35，128 条完整窗口、34 条即将开放、94 条关闭、1 条未公布窗口。英语交叉核对发现两个标题变体及英语入口额外的一条双学位记录，明确记为来源不一致。任一详情失败、ID／链接重复、总数不符或已展示日期无法解析均使对应本轮失败。
CZU 博士适配器把 MŠMT 紧凑库存中的 60 个博士 offering 与六学院官方 2026/27 规则逐项匹配。2026-09-11 实跑取得 9/9 个官方资产、60/60 项匹配、捷克语与英语各 30 项，六学院均有项目和窗口证据；按抓取日 60 项全部关闭。34 项至少有一个起止完整窗口，其余来源只公布截止日；三项 FTZ 后续阶段附带名额条件。未知开始日和条件阶段不产生开放状态，TF 图像 PDF 的审核转录以精确内容哈希保护。该轮不能证明 2027/28 是否已在其他页面发布，也不能推断未公告的补录轮次。
数据库暂停、主机离线或网站访问限制会阻止自动更新，应报告运行失败，不能显示“刚刚更新”。部署环境必须支持持久调度；个人电脑开机运行不满足正式运营要求。

## 捷克高校广覆盖

以当前官方高校名录为基线，逐校登记公立、国立、私立、university / non-university 类型。应用／职业导向按官方证据标注；VOŠ 独立分类。
不以排名、城市、是否存在英文官网作为收录门槛。英语与捷克语项目均采集；没有英语项目的学校也保留机构记录，明确其语言覆盖。
首先接入学校官方目录，再向学院招生页细化。每所学校登记项目页、招生页、语言页及招聘页；不存在的来源标“不适用”，不能当抓取成功。
分开报告：名录登记率、来源接入率、每轮来源成功率、项目覆盖情况、英语／捷克语项目数量、失败／待核验来源。`services/ingestion/src/build_source_coverage.py` 以 54 所 MŠMT 高校为固定分母生成 `data/sources/coverage/source-coverage.json`；它必须同时保留“完整来源快照”和“完整招生／招聘目录”两个不同结论。
内部首发目标：官方基线学校登记 100%，至少 95% 学校具有有效官方来源映射，每轮有效来源成功率至少 90%。这些是建设目标，不是已经达成的覆盖数字。缺口逐项说明，分母固定到该轮基线版本。
没有完整官方项目总数时，不能宣称项目覆盖 100%；公开“已核验项目数与尚未覆盖学校／学院”。不得把学院当独立学校扩充数量。

## 自动下架与发现延迟

- 已知明确截止时间：每分钟扫描并在公开读取时再次判定，不等待五天采集；以源时区和精度为准。只给日期的公告按该地日期结束判过期，说明这是平台展示规则，不代表雇主承诺最后提交时刻。
- 官网明确标注 closed、filled、withdrawn 等有效关闭证据：更新状态并自动下架。
- 申请系统明确停止接收该岗位申请：核查是正确职位后关闭入口，下架并保留证据。
- 404、403、429、超时、验证码不独立等于招聘结束。失败重试，必要时暂记 unavailable 并暂停展示，保留不同于 closed 的原因；官方公告／招聘目录确认撤销后再标 closed。
- 无截止、招满即止岗位：每五天稳定资料刷新之外，每 1 小时轻量检查已知岗位官方状态与申请链接。新岗位由 4 小时完整目录发现任务补入候选。提前关闭或新增仍可能存在一个检查周期、抓取、重试、人工三语审核与安全发布延迟，不能宣称瞬时实时。
- 下架事务同步三语列表、搜索索引、推荐与缓存，失效目标不超过 5 分钟。保留内部归档；旧收藏或直达详情显示已关闭并禁用申请。
- 恢复招聘需新开放证据；重新可访问不自动代表重新招人。

岗位复核必须保留每个独立 `windowId`、原顺序、时区和日期精度。逐轮关闭后再汇总机会：一轮结束而另一轮开放或未来补录存在时，不关闭整岗；只有官方整岗关闭证据或全部适用轮次确认结束，才生成整岗关闭状态。请求失败保留 last-good 窗口和申请入口，并记录失败，不把 503 或解析为空写成成功。

注册来源当前驱动 Charles University、MUNI、UPOL、VŠB-TUO、UCT Prague、CTU、VUT、CZU 与 AVCR 招聘列表的分页和详情发现。Charles 读取 AJAX 真分页；VUT 读取校级门户公开的 GraphQL 列表与全文；CTU 校级公告板读取精确总数、详情与 PDF，扫描件使用有大小和页数上限的本地 OCR；CZU 将 WP Job Manager 公共分页与同站 REST 全文按岗位 ID 交叉核对。只有列表、分页、详情和必要附件全部成功时，旧动态岗位从目录消失才转为 `unavailable`；仍在目录但不再符合研究／技术范围的记录改为 `catalogueScopeStatus=excluded`，不得伪称官网消失。AVCR 候选必须先解析实际研究所雇主，无法归属的记录进入隔离区。动态发现本身不等于发布，新岗位还须完成资格证据和逐语种人工审核。

截至 `2026-09-11T19:46:56Z` 的本地覆盖证据是 10/10 已登记来源运行成功、8/54 所 MŠMT 高校有来源映射。8 所有校级聚合入口，CTU 另有 FEE 院系补充源，0 个来源声明校内岗位完整覆盖；AVCR 是独立研究机构集合。当前运行层有 64 条范围内候选，其中 20 条符合严格带薪硕士范围；活动不可变快照仍只有 4 条完成三语审核的正式岗位。该数字只描述接入面、来源深度和审核层级，不能推断其余 46 所学校没有岗位，也不能把中央聚合入口自动视为该校岗位全集。

## 点击直达官方申请

岗位标题和主要“立即申请”按钮直接使用官方 applicationUrl。站内详情仅作为独立次级说明入口，不强迫多点一次，不要求本站账号。
sourceUrl 保存公告证据，applicationUrl 保存实际提交入口，二者允许不同。雇主官网指向的第三方 ATS 可收录，必须保存其官方指向证据和验证时间。
优先精确职位申请页，其次明确包含申请步骤的官方公告；不得退化为学校首页或泛招聘首页却仍称“立即申请”。
只有邮件申请时跳转官方申请说明，按钮改为“查看官方申请说明”；不自动发送邮件、不伪造网页表单。
限制为经核验的 HTTPS 官方或官方指定目标，拦截 javascript/data 等非网页协议；禁止收录含个人会话凭据的链接。追踪点击不得形成任意开放重定向。
界面切换语言不改变申请目标；官方申请系统本身未必支持中英捷三语，要明确这是外部网站。

## 多轮申请对下架的补充

计时与下架以 ApplicationWindow 为单位先判定，再汇总所属机会。当前轮次结束但下一轮开放时，自动切换到当前有效轮次，不下架整个机会；只有未来轮次时标未开放并禁用当前申请入口。
官网明确整个岗位关闭／招满优先于历史轮次安排。标题直达当前适用窗口的官方链接，多个窗口同时开放且人群不同，应提供各自标明人群的直达链接，不能任意选择错误轮次。
